# RndrGL.dll — OpenGL draw path (which entry points the engine actually uses)

# purpose : GH #63 / GH #66 (approach 2). Approach 1 (forcing the RPG item's
#           `noviewmodel` bit) was falsified (ADR-0438: engine-toggled, no reader).
#           Approach 2 suppresses the first-person viewmodel at the draw level, so
#           we must know which GL draw entry points the renderer (RndrGL.dll)
#           actually calls. Read-only artefact of REA; no game file is modified.
# target  : C:\Program Files (x86)\Starbreeze Studios\Riddick EFBB
#           (2004 *Escape from Butcher Bay*; see ADR-0413/0414 for the build pin)

## 1. Which module imports OpenGL

Only **RndrGL.dll** imports OpenGL entry points (x86 `System/Win32_x86/RndrGL.dll`,
plus the SSE / SSE2 / Win64 builds). MXR.dll, MSystem.dll, MCCDyn.dll,
SbzEngine.exe, GameClasses_Win32_x86.dll and GameWorld_Win32_x86.dll contain no
`gl*`/`wgl*` import names. => RndrGL is the single GL client, so a hook installed
in RndrGL.dll's import table sees every engine draw.

## 2. The geometry (mesh) path is glDrawElements

| entry point            | x86 RndrGL | any shipped module |
|------------------------|-----------|--------------------|
| `glDrawElements`       | present   | present (all RndrGL builds) |
| `glDrawArrays`         | **absent**| **absent**         |
| `glDrawRangeElements`  | absent    | absent             |
| `glInterleavedArrays`  | absent    | absent             |
| `glBegin` / `glEnd`    | present   | present (RndrGL)   |
| `glCallList`           | present   | present (all RndrGL builds) |
| `glNewList`/`glGenLists`/`glEndList` | **absent** | **absent** |

- `.xmd` meshes ship indexed geometry (`TRIANGLES` = `u32 count` + `u16`
  indices; ADR-0415/0416), consistent with an **indexed vertex-array** path.
- `glDrawArrays` is used by **no** shipped module, so indexing `glDrawElements`
  is the reliable per-mesh gate. (The proxy still exports `glDrawArrays`
  (`src/hook/opengl32.def`), but it is dead for this title.)
- `glBegin`/`glEnd` are imported (immediate-mode / 2D path). They are **not**
  intercepted in this pass: suppressing `glBegin` without the matching `glEnd`
  would be a GL error, so a begin/end pair gate is left as a follow-up if the
  first-person arms turn out to use immediate mode.

### Open question: the display-list path
`glCallList` is imported by RndrGL, but **no** shipped module imports the list
*building* entry points (`glNewList`/`glGenLists`/`glEndList`) and the OpenGL
metafile playback names (`GlmfPlayGlsRecord`, `GlmfBeginGlsBlock`, ...) appear in
**no** module either. So either `glCallList` is an unused import, or the list IDs
come from a path not yet located. `glCallList` is intercepted opportunistically
(it is a no-op change when the suppressor is off); nothing depends on it.

## 3. The matrix / state vocabulary (constrains the signature)

Present in RndrGL: `glLoadMatrixf`, `glLoadIdentity`, `glPushMatrix`,
`glPopMatrix`, `glTranslatef`, `glFrustum`, `glClear`, `glClearDepth`,
`glViewport`, `glScissor`, `glDepthFunc`, `glDepthMask`, `glPolygonOffset`,
`glColorMask`, `glStencilFunc`, `glTexEnv*`, `glCallList`.

**Absent** (notable negatives): `glDepthRange`, `glMultMatrixf`,
`glMultMatrixd`, `glRotatef`.

- Because `glDepthRange` is not imported, the "bias the viewmodel into a
  sub-range" trick is **not** used, so depth-range is *not* a usable signature.
- Object transforms are composed from `glLoadMatrixf` + `glPushMatrix`/
  `glTranslatef`/`glPopMatrix` (no `glMultMatrixf`/`glRotatef`), i.e. the engine
  loads/translates matrices directly; both `glLoadMatrixf` and `glFrustum` are
  already intercepted by the hook (projection loads close the suppression
  window).

**Consequence for the draw-time matrix capture (GH #67 step 1).** Because a pushed
sub-object is `glLoadMatrixf(base)` then `glPushMatrix(); glTranslatef(...)`, the
matrix in effect at a draw is `base * translate(...)` -- not the base that
`glLoadMatrixf` alone records. The hook therefore mirrors the `GL_MODELVIEW` stack
(`src/hook/gl_matrix_tracker.h`) and IAT-hooks `OPENGL32.dll!glLoadIdentity`,
`!glPushMatrix`, `!glPopMatrix` and `!glTranslatef` in RndrGL so the reported
draw-time modelview is the effective one (ADR-0451).

### Correction (ADR-0481): on the 2009 target the modelview is a dead end

section 3 above is the **2004** module. On the live target (the 2009
`System/Win32_x86/RndrGL.dll`, 939248 bytes, 05-Mar-12) the same measurement
reproduces the same vocabulary -- **and a live run shows the stack is not used**:

- Live (8790 frames, `RIDDICKVR_SIM=1`, `ViewmodelObserve=1`, read-only shadow
  install): the hook log carries exactly **one** `glLoadMatrixf [MODELVIEW #1]`
  (identity) for the whole run, 405 `glLoadMatrixf [3D VR PROJECTION …]` loads,
  and **zero** `glFrustum` calls. The probe reads `pushes=0 translates=0` on
  every sampled frame while all six RndrGL IAT hooks log as installed. So the
  engine's only modelview load is an identity and it never calls
  `glPushMatrix`/`glTranslatef`.
- The 2009 `RndrGL.dll` **does** reference the ARB_vertex_program entry points
  (`glProgramStringARB`, `glBindProgramARB`, `glGenProgramsARB`,
  `glDeleteProgramsARB`, `glProgramEnvParameter4fvARB`, `glProgramEnvParameter4fARB`,
  `glGetProgramivARB`, `glGetProgramStringARB`) and the generic-attribute path
  (`glVertexAttribPointer`/`…ARB`, `glEnableVertexAttribArrayARB`,
  `glVertexAttrib4fARB`; **no** `glTexCoordPointer`), and does **not** reference
  `glMultMatrixf`/`glMultMatrixd`/`glLoadMatrixd`/`glRotatef`/`glScalef`.

So the ARB program path was the natural *candidate* for the object/view
transforms (and `GetLastViewMatrix()` can never be the viewmodel transform,
whichever fixed-function entry point is hooked) -- but that candidate was then
measured and it is **silent live** (below). Note the ARB names are **not** in the
static import table: they can only be resolved through `wglGetProcAddress`, which
is where the hook intercepts them. The matrix-stack mirror is kept (correct
semantics, unit-tested, cheap) but is provably inert on this title. Reproduce the vocabulary with
`python tools/gl_vocabulary_scan.py --game-dir "<install>"` (read-only); add
`--imports` for the authoritative static import table (the 2009 `RndrGL.dll`
binds exactly 96 OpenGL 1.1 entry points from `OPENGL32.dll`, no ARB ones, and
its legacy immediate-mode vocabulary -- `glBegin`/`glEnd`, `glVertex3f`/
`glVertex3fv`, `glNormal3fv`, `glTexCoord*`, `glColor*`, `glMaterialfv`,
`glLight*`, `glClipPlane`, `glTexGen*` -- so it is a fixed-function immediate-mode
renderer).

**Measured live, twice (ADR-0481):** with both env-parameter spellings
(`glProgramEnvParameter4fvARB`, `glProgramEnvParameter4fARB`) intercepted, a 45 s
gameplay run logs 23 sampled `ViewmodelProbe program` lines with
`strings=0 binds=0 env=0` -- the ARB program path is not called either. Together
with the identity modelview and the (per-view, not per-object) projection loads,
the object/view transform is **not in GL state**: it is applied on the engine
side to the submitted vertex data. Any GH #67 drive path must hook that, not a
GL matrix.

**Measured live (ADR-0482):** that inference is now an observation. The hook
samples the client vertex array at the first array draw on each side of the
first-person window (`glVertexPointer` is imported by RndrGL; `glDrawArrays` and
any `glBindBuffer*` are not, so the pointer is always a plain client pointer) and
counts `glDrawElements` vs `glCallList` by side -- logged as
`ViewmodelProbe submission [#N]: arrayIn=… listIn=…` plus a
`ViewmodelProbe submission fp:` / `… world:` geometry line. `listIn > 0` with
`arrayIn == 0` would mean the first-person pass is display-list geometry (its
vertices replay inside the driver and no draw-time sample can see it). See
ADR-0482 and `src/hook/vertex_submission_observe.h`.


## 4. Consequence for the suppressor (GH #66)
- Interception targets: **`glDrawElements`** (primary; every 3D mesh) and
  **`glCallList`** (opportunistic). Both are IAT-hooked in `RndrGL.dll`
  (`src/hook/dllmain.cpp`, `InstallRndrGLHooks`) via the same `IATHook` used for
  `GDI32!SwapBuffers`.
- Window signals come from entry points the hook **already** intercepts:
  `glClear` (a mid-frame depth-only clear opens; a full colour clear re-bases the
  frame) and the projection loads `glLoadMatrixf`/`glFrustum`/`glOrtho` (close).
- The window logic is in `src/hook/viewmodel_suppressor.h` (unit-tested by
  `viewmodel_suppressor_window`, `tests/viewmodel_suppressor_tests.cpp`).
- PROVISIONAL: the "depth-only clear opens the first-person pass" signature is a
  hypothesis. It is off by default (`SuppressEngineViewmodel=0`) and the hook
  logs per-frame draw/suppressed counters so one in-headset run confirms it
  before it is trusted (see ADR-0439).

## not claimed
- Not verified in-game (no launch): the depth-only-clear boundary, the count of
  draws in the window, and whether `glDrawElements` alone hides the arms.
- The origin of the `glCallList` list IDs is unresolved (section 2).
- These offsets are for the 2004 EFBB x86 build; the Dark Athena build is not
  scanned here (ADR-0413 target mismatch).
